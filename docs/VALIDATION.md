# 本机验证记录

环境：Apple M4 Max，36 GB 内存，macOS 26.0.1，Swift 6.2.4 / Command Line Tools。验证使用 Release 应用，默认 2 秒采样。

- Debug 与 Release 编译通过，无第三方包。
- `swift run LscpuCoreChecks`：7 组检查全部通过，涵盖 CPU、网络差值、网络切换 / 回退 / 断网、休眠间隔、多接口、历史硬上限、格式化与实际 API。
- 真实诊断确认 GPU、CPU、内存可以读取，网络只识别实际活动的 en0，未连接的 en1–en6 不再被算作活动链路。
- 电量已从菜单栏、弹窗、设置、模型和采集器中移除。
- 原生 Popover 实测内容矩形 `(-1042, 873, 368, 528)`，屏幕可见区域 `(-2560, 0, 2560, 1409)`，内容完全位于可见区域内。检查模式临时使用 applicationDefined，避免外部应用抢占焦点打断几何验证；正式运行使用 transient，点击外部会关闭。
- 预览使用真实采样 64 秒数据，已检查浅色 / 深色图片，标题及底部完整，四类指标均显示。
- 关闭弹窗的后台进程：10 秒 RSS 49,568 KB，30 秒 49,728 KB，60 秒 51,360 KB；累计 CPU 时间分别 0.12、0.25、0.37 秒。ps 的瞬时 CPU 显示为 0.0%，不意味着完全没有 CPU 使用。
- `codesign --verify --deep --strict dist/Lscpu.app` 通过；Info.plist 语法校验通过。

上述资源数据是短时观测，不是长期无泄漏或耗电保证。尚未覆盖长时间压力测试、所有 Mac 型号、所有显示器 / 缩放 / 刘海布局、实际睡眠唤醒、不同网络设备的物理切换、登录启动重启，以及 Developer ID 公证分发。相关差值与睡眠边界已通过程序化检查。GPU 驱动字段的跨系统可用性见 README。

## 2026-10-17 菜单栏入口修复

在 1512 × 982 的带刘海内置屏上复现：项目宽 240 pt，位于 x=291，超出右侧可用区域 x=848…1512，但 AppKit isVisible 仍为 true。为本应用新 autosaveName 初始化右侧位置后，项目位于 x=1041…1281，完整落在右侧可见区域。初始化位置利用 AppKit 的 NSStatusItem Preferred Position 偏好项；该键不是稳定的公开接口，因此另有根据实际窗口几何自动收缩的处理。现有用户位置不会在每次启动时重置。

增加空间不足时的 16 pt 波形图标降级，显示器切换或重新打开应用后重试完整布局；程序主循环显式持有 delegate，避免优化构建中的生命周期歧义。
